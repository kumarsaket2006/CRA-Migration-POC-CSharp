1. Executive summary

The legacy library had 58 distinct security findings across dependencies, code, secrets and architecture review, and it ran on an unsupported runtime. After the .NET 10 migration with CRA remediation, 5 remain: one triaged SAST item in a developer tool and 4 documented residual risks. None of them is critical or high.

Residual risks after migration (4)

SeverityRiskCRATreatment
MEDIUMMR-F01 Modbus TCP field protocol is unauthenticated by design
The southbound Modbus/TCP link cannot authenticate or integrity-protect frames. Compensating controls: gateway acts as the only conduit into the cell zone (IEC 62443-3-3 zones/conduits), simulator/devices bound to the control VLAN, strict response validation in ModbusFrame. Roadmap: Modbus/TCP Security (TLS, port 802) for devices that support it.		Annex I Part I (2)(d)(j)accepted-with-compensating-controls
LOWMR-F02 Device-side firmware authenticity depends on the device bootloader
The gateway verifies signature, model binding and anti-rollback before staging. The final flash step must be verified again by the device (secure boot); this belongs to the device's own CRA assessment.		Annex I Part I (2)(c)out-of-scope
LOWMR-F03 Client certificate allow-list requires lifecycle management
Certificate rotation, revocation (CRL/OCSP reachable from the OT network) and allow-list updates are documented in the secure configuration guide; an expired or revoked certificate fails closed.		Annex I Part I (2)(d)mitigated-by-process
LOWMR-F04 Firmware/license signing key held as PEM in the POC
fg-sign reads a PEM private key for demonstration. Production signing must use an HSM / Azure Key Vault key with dual control; only public keys are deployed to gateways.		Annex I Part I (2)(e)open-production-action
